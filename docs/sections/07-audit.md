# 第三部分 · 智能体如何进入审计工作（章节14—19）

- **主线时长：** 60分钟
- **贯穿场景：** 采购与合同管理专项审计
- **三个案例：** 异构审计资料解析 → 智能问数与数据分析 → 智能生成审计报告
- **教学方式：** 先给真实任务和明确选择，解释选择后果，再逐步补齐工具、知识、权限、证据与人工关口
- **统一设计问题：** 目标、输入、知识、工具、权限、验证

## 14 · 从审计工作链理解三个智能体（6分钟，`#audit`）

项目组同时收到扫描合同、附件、现场照片、电子表格台账、文字处理制度、系统导出数据、历史报告和整改材料。学习者先选择：

1. 全部内容直接交给大语言模型；
2. 先识别文件类型、可读性和安全状态；
3. 将所有文件转换成图片。

选择后立即显示可靠性原因。课件由此引出三个**并列**智能体（14.2 不使用 01/02/03 序号，避免被读成必须串行）：

- 资料解析智能体解决“资料怎样进入系统并形成可靠证据”；
- 智能问数与分析智能体解决“怎样安全准确地找到数字并分析”；
- 报告生成智能体解决“怎样把事实、证据和分析组织成报告”。

`AuditDesignWorkbench`持续展示六个设计问题（并列检查项，无序号），并支持三个案例切换。

## 15 · 异构审计资料解析智能体（12分钟，`#audit-documents`）

`DocumentParsingLab`集中管理四类教学文件：

- 扫描文档：页面拆分、方向纠正、去噪、文字识别、版面重建、质量检测；
- 电子表格：工作表、标题行、合并单元格、单元格值、公式结果、字段与单元格来源；
- 文字处理文档：标题、段落、编号、表格、批注、修订、页眉页脚和属性；
- 图片：方向、文字、视觉内容、区域定位与低置信度标记。

每种文件展示类型边界、中间结果、原始位置、置信度、解析问题和“直接采用/校验/丢弃”三个选项。正确做法是校验并保留来源；低置信度内容转人工。

统一证据对象至少保留文档身份、来源、权限、内容类型、页码或单元格、置信度、原始定位和复核状态。`EvidenceConflictBoard`展示合同正文860万元、付款台账830万元、审批表860万元的冲突，系统保留三个来源并提出核查方向，不擅自选择。

## 16 · 智能问数与数据分析智能体（12分钟，`#audit-data`）

贯穿问题：2025年上半年各二级单位单一来源采购金额、同比最高单位及主要供应商贡献。

`SecureQueryLab`完整展示：

1. 身份和权限；
2. 指标口径；
3. 数据字典与业务语义层；
4. 查询计划；
5. 查询语句草稿；
6. 安全校验；
7. 权限条件注入；
8. 只读环境执行；
9. 结果复算与分析。

总部审计人员、天津分公司审计人员和当前项目组成员看到不同授权单位。权限范围由身份和权限服务提供，模型不得填写或扩大。

安全校验包括只读单语句、表字段白名单、组织/项目/行/字段权限、扫描范围、返回行数、超时、敏感字段脱敏、异常关联与危险函数检查、完整日志。前端只使用模拟数据，不连接真实数据库。

结果除金额外还展示同比、排名和供应商贡献因素，并保留原始问题、指标、口径、权限、数据表、执行语句、查询时间、数据更新时间、记录数和脱敏状态。

## 17 · 智能生成审计报告（15分钟，`#audit-report`）

从“根据现有资料写报告”的失败方式开始，强调报告生成重点不是语言像报告，而是结构、事实、证据、制度、模板、风格和审批均可控制。

生成前建立六层知识：

1. 报告结构；
2. 类型模板；
3. 审计问题表达；
4. 版本化制度依据；
5. 经过批准、分类、脱敏的历史案例；
6. 可查看和编辑的单位/个人风格规则。

`ReportArchitectureBoard`展示事实证据层→审计分析层→报告表达层，三层不可颠倒。初期技术路线优先采用结构化模板、发现数据模型、证据绑定、检索增强生成、风格配置、分章节生成、规则校验和人工审核；微调不能替代证据检索与事实校验。

`ReportGenerationStudio`支持：

- 报告类型选择；
- 结构化发现和证据状态；
- 风格规则切换；
- 提纲上移和下移；
- 章节正文、证据和质量检查三栏审核；
- 接受锁定、退回修改和恢复待审；
- 修改与版本记录。

质量门覆盖数字、事实、证据、制度版本、不确定性、模板和风格。证据不足时阻断确定性结论。

## 18 · 三个智能体如何协作成完整审计系统（7分钟，`#audit-collaboration`）

18.1先交代审计任务背景：对项目甲做采购与合同初步分析——输入为合同扫描件、付款台账、供应商材料与平台采购宽表；要核对合同与台账金额、供应商趋势与单一来源异常，并形成供项目组讨论的报告草稿，正式定性仍由人复核。

`AuditCollaborationLab`用十二步演示该任务，并标明每步责任智能体：

1–3 资料解析智能体：资料包解析 → 字段提取 → 金额冲突；
4–6 智能问数与分析智能体：历史采购问数 → 供应商趋势 → 单一来源异常；
7、9–11 报告生成智能体：制度检索 → 报告提纲 → 问题建议草稿 → 展示证据与查询语句；
8、12 审计人员：确认结构化发现、复核正式草稿。

三个智能体共享用户身份、组织/项目/文件/数据权限、证据编号、审计知识、工具注册、任务状态、操作日志、人工审批、安全控制、模型调用和版本管理。

对象接口分为证据对象、查询结果对象、审计发现对象和报告对象，使报告句子可以回到发现、查询和原始文件。

## 19 · 效果、评估与治理边界（8分钟，`#audit-governance`）

`AuditGovernanceDashboard`切换具体效果、评估指标和治理边界：

- 资料解析：成功率、文字准确率、表格还原、来源覆盖、冲突召回和人工修正；
- 智能问数：意图与口径、执行成功、权限隔离、数字一致、风险拦截；
- 报告生成：事实忠实、数字一致、证据覆盖、制度版本和人工退回。

责任链严格区分：原始证据 → 工具提取事实 → 系统分析 → 智能体建议 → 审计人员确认 → 正式审计结论。

安全边界覆盖数据、身份权限、查询、报告、操作与正式责任。系统不得把内部资料发送到未经批准的服务，不得在前端保存真实密钥、数据库密码或内部地址。
