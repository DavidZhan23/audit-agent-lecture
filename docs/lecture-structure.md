# 整堂课结构总览

**最后核对代码：** `app/page.tsx` → `export default function Home`  
**课程标题：** 大语言模型与智能体：基础、架构及审计应用

## 三层总体架构

1. **第一部分：大模型和智能体的技术基础**——基于任务逻辑的编程 → 机器学习 → 神经网络 → 大语言模型，解释技术为什么逐层出现。
2. **第二部分：从大语言模型到智能体**——从一次调用的行动缺口出发，逐步加入知识、工具、状态、计划、权限和人工监督。
3. **第三部分：智能体在审计中的应用**——把通用能力组合成受控、可复核、可评价的审计智能体。

第一部分建立能力底座，第二部分搭建企业智能体运行系统，第三部分用审计工作产品、证据和责任边界约束该系统。

## 页面组织方式

课件采用23页分页模式：课程封面、导言、三个部分总览页和19个正式章节页。一次只显示当前页。

- 底部提供上一页、下一页、当前页码和完整目录。
- 左侧目录可直接跳转并支持隐藏；移动端以抽屉形式打开。
- 方向键、翻页键用于前后翻页，首尾键跳到第一页或最后一页。
- 打印时展开全部页面。
- 页面保持分部分渐变、细点纹理、章节色带和卡片式图示；不增加无关装饰动画。

**图示序号约定：** 并列模块/边界/能力/检查项不使用 01、02… 序号；有先后关系的流程用序号，并用箭头（→ / ↓）标出方向。章节导航、页码与测验题号除外。

## 第一部分：技术基础（`#part-1`，章节02—05）

第一部分保持原有教学结构。04用“两位室友自制人脸门禁”的课堂虚构案例说明：神经网络输出笑雨/骐源/其他三类概率，应用规则只在两位室友达到阈值时模拟开门，其他或低置信度结果保持关闭；训练流程之后直接进入真实模型的操作按钮区，不设置单独的演示标题栏。05使用合同示例串起文字数字化、上下文处理、海量文本训练和回答生成；5.5把前文串成一次完整对话生成：对话模板→Tokenizer→Token ID→Embedding→Transformer Block→LM Head→概率分布，再通过Prefill、逐Token Decode与模型外生成循环讲清回答如何逐步形成。结尾明确：大语言模型能够理解和生成，但不能天然持续保存状态、调用外部工具并执行现实任务，由此自然进入06。

## 第二部分：从大语言模型到智能体（`#part-2`，章节06—13）

1. **06 行动缺口（`#agent`）：** 合同问题的一次回答与真正完成检查的八类工作对比；正式提出“主合同甲转分包风险识别”贯穿案例，并明确用户需要的是带证据、依据、不确定项和复核建议的可复核的初步分析报告。
2. **07 定义与组成（`#agent-definition`）：** 承接06的同一任务观察克制定义；目标、模型、上下文、知识、状态、工具、规则权限和运行机制互动架构。
3. **08 运行循环（`#agent-loop`）：** 继续运行06提出的同一任务；九步转分包检查模拟器逐步展示目标、状态、工具输入、工具输出和下一步判断。
4. **09 知识型（`#agent-knowledge`）：** 制度知识助手；答案、条款位置、版本、来源、冲突和权限。
5. **10 任务型（`#agent-task`）：** 会议纪要与任务分发；内部试点会的录音和材料先形成结构化纪要，含糊日期触发人工补充，权限校验后再写入任务并发送确认。
6. **11 规划型（`#agent-planning`）：** 沿用09—10的三类智能体统一框架并默认选中规划型；11.2先交代近一年核心系统故障根因专项排查的目标、交付与难点，再演示全量初筛后从标题匹配调整为现象/错误语义匹配，并新增材料补充任务。
7. **12 组合应用（`#agent-case`）：** 完整展开前文贯穿案例的主合同与候选合同卡片、八步时间线、三类能力组合、人工确认节点和证据化结果。
8. **13 价值与边界（`#agent-value`）：** 五类工作方式变化、模型与工具错误、治理机制和第二部分演化链。

海能智能体平台当前采用知识型、任务型和规划型三类业务分类。课件明确该分类不是唯一行业标准，三类能力可在同一应用中组合。

统一技术边界：大语言模型不等于智能体；工具由应用层校验和执行；对话历史不等于永久记忆；动态计划不扩大权限；高风险动作、证据冲突和正式审计结论必须设置人工关口。

## 第三部分：智能体如何进入审计工作（`#part-3`，章节14—19）

1. **14 工作链与三个智能体（`#audit`）：** 以采购与合同管理专项审计开场，用明确选项让学习者判断“全部资料直接交给模型”为什么不可靠，再建立资料、数据、成果三环节和统一六问工作台。
2. **15 异构审计资料解析（`#audit-documents`）：** 扫描文档、图片、电子表格和文字处理文档分别路由；保留置信度、页码、单元格、结构、权限和原始位置；跨文档冲突不自动裁决。
3. **16 智能问数与数据分析（`#audit-data`）：** 自然语言问题先形成业务指标和查询计划；三个身份切换展示权限隔离；查询语句通过白名单、权限注入、扫描限制、脱敏和只读环境后执行，再完成同比、排名和贡献因素分析。
4. **17 智能生成审计报告（`#audit-report`）：** 历史报告按类型、版本、批准状态与保密等级治理；建立结构、模板、问题表达、制度、批准案例和风格六层知识；事实证据→审计分析→报告表达；先提纲、后分段、逐句人工审核。
5. **18 三个智能体协作系统（`#audit-collaboration`）：** 18.1先交代项目甲采购与合同初步分析任务背景；再以十二步演示资料解析、问数分析与报告生成协作，并共享身份、权限、证据编号、任务状态与审批。
6. **19 效果、评估与治理（`#audit-governance`）：** 分别评价资料解析、智能问数和报告生成；严格区分原始证据、提取事实、系统分析、智能体建议、人工确认和正式结论。

统一边界：模型不直接精确解析所有文件、不猜审计数字、不自行决定权限、不直接连接生产数据库、不虚构制度或事实，也不能自动认定违规、舞弊或签发审计意见。
